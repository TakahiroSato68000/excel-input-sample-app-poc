# 要求仕様書：ローカル完結型データ入力・一括印刷システム (PoC)

## 1. はじめに

### 1.1. 背景
現在、手作業または個別の Excel 入力で行っているデータ管理・帳票印刷業務において、管理負担が課題となっている。多くの業務は、入力が散在し、締め処理や印刷まで手作業で進められており、ミスや時間のロスが発生している。

### 1.2. 目的
本プロジェクトは、ブラウザから手軽に入力でき、1 日の終わりに一括して既存フォーマットで印刷できる Web アプリケーションを構築し、業務の習熟・検証・演習を効率化することを目的とする。特に本 PoC は、利用者が簡単に操作を体験できることを重視し、権限管理や本格運用機能は後段の拡張とする。

### 1.3. 本 PoC の前提
本システムは、ローカル環境で動作する簡易な演習用アプリケーションとして設計する。ユーザーごとの権限管理や高度な認証機能は実装対象外とし、1 人または少人数での簡易な操作を前提とする。

### 1.4. 採用技術
本 PoC では、以下の技術を採用する。
- Python
- FastAPI
- HTML
- JavaScript

本技術構成により、ローカル環境での簡易な Web アプリを短期間で構築し、入力フォーム、保存処理、Excel 生成を実現する。

---

## 2. 対象業務とスコープ

### 2.1. 対象業務フロー
1. 日中の入力: 利用者がブラウザから入力画面へアクセスし、必要なデータを入力する。
2. 一時保存: 入力内容をその場で保存し、再編集や後続入力に利用できるようにする。
3. 一日の終わりに確定: まとめて確認し、Excel 形式に出力する。
4. 帳票印刷: 生成された Excel ファイルを既存フォーマットで印刷する。

### 2.2. システム化の範囲
- 対象: 入力画面、一時保存、Excel 一括出力、バックアップ、名簿読み込み
- 対象外: 権限管理、ユーザー認証、名簿編集機能、共有サーバー連携、クラウド保存

---

## 3. 機能要件

### 3.1. 入力画面要件
- 日付入力項目:
  - 初期表示時に当日の日付（YYYY-MM-DD）を自動表示すること。
  - 過去日・未来日も手入力可能とすること。
- 名前入力項目:
  - 氏名候補の一覧を先に表示し、候補から選択して入力できること。
  - 入力中に候補を自動表示しないこと。
  - 名簿に存在しない場合でも、自由入力可能とすること。
  - 候補が存在する場合は選択で入力し、候補がない場合は直接入力すること。
- 社員番号連動:
  - 名前選択時に、対応する社員番号を自動で関連付けて入力すること。
  - ただし、直接編集も可能とすること。
- 時刻入力項目:
  - 開始時刻には画面表示時刻を初期値として設定すること。
  - 終了時刻は空欄で開始し、必要に応じて入力可能とすること。
- その他入力項目:
  - 理由、備考は任意項目とする。
- 一時保存機能:
  - 入力データを画面遷移なしで保存すること。
  - 保存結果として成功/失敗メッセージを画面上に表示すること。
  - メッセージは入力フォーム、一覧表、Excel 生成ボタンの下に表示すること。
- 入力結果一覧表示:
  - 入力フォームの下に、保存済みデータを表形式で表示すること。
  - 表には日付、社員番号、氏名、理由、開始時刻、終了時刻、備考を表示すること。
  - 画面上で選択中の日付に応じて対象データを絞り込み、保存後には最新状態へ自動更新すること。
- 確定処理:
  - 画面上に「Excel 一括出力（確定）」ボタンを配置すること。
  - 本 PoC では、利用者ごとの権限分離は行わず、誰でも実行可能とすること。

### 3.2. データ管理要件
- 保存形式:
  - 入力データは Excel ではなく、JSON 形式で軽量に保存すること。
  - 保存は追記形式または日次ファイル形式を採用し、ファイルの破損を避けること。
- 重複時の扱い:
  - 同じ社員について、同じ日付のデータが既に存在する場合は、最新の入力内容で上書き保存すること。
  - 保存の結果として、当日分の JSON には同一社員のレコードが 1 件だけ残ること。
  - 社員判定は社員番号を優先し、社員番号が未入力の場合は氏名で比較すること。
- 一時保存の保持期間:
  - 確定処理前のデータは保持し、再印刷や修正に利用できるようにすること。
- 一時保存のクリア:
  - 翌日以降の最初の新規入力時に、前日の一時保存データを自動的に初期化すること。
- 自動バックアップ:
  - 確定処理の際、既存の Excel ファイルが存在する場合は、backup フォルダに退避すること。

### 3.3. Excel 生成要件
- 既存の template.xlsx を元に、当日の日付をファイル名に付けた新しい Excel ファイルを生成すること。
- 生成対象ファイル名は YYYY-MM-DD.xlsx とすること。
- 一時保存済みデータをすべて読み込み、1 回で一括挿入すること。
- 生成後の Excel ファイルは、既存の印刷レイアウトを維持したまま紙出力できる状態とすること。

### 3.4. 再印刷・修正要件
- 確定処理後も一時保存ファイルは削除せず保持すること。
- 誤字・脱字が見つかった場合でも、再度 Excel 出力を実行できること。
- ただし本 PoC では、厳密な履歴管理や差分追跡は対象外とする。

---

## 4. 非機能要件

- 採用技術:
  - Python をバックエンド言語とし、FastAPI を用いて Web API を実装すること。
  - フロントエンドは HTML と JavaScript を用い、ブラウザ上で入力フォームとメッセージ表示を行うこと。
  - 画面表示・イベント制御は JavaScript で実装し、サーバー側との通信は HTTP API 経由とすること。
- マスタデータの独立:
  - 社員名簿はソースコードに直接記述せず、外部ファイル（roster.json）から読み込むこと。
- 拡張性:
  - 将来 SharePoint などへ置き換える際、画面や業務ロジックに影響が出にくいよう、I/O 処理を分離した構造とすること。
- 環境条件:
  - 専用の Web サーバーを立てず、Windows PC 上または同一 LAN 内からブラウザで利用できること。
- 研修用途:
  - 初心者でも操作手順がわかりやすいように、画面・メッセージ・処理フローを簡潔にすること。
- 権限管理:
  - 本 PoC では、ユーザーごとの権限差分や認可機能は実装対象外とする。

---

## 5. データ項目定義

入力データの基本項目は以下とする。

- 日付
- 社員番号
- 氏名
- 理由
- 開始時刻
- 終了時刻
- 備考

上記項目は、Excel 出力時に固定列順で書き出すこと。

---

## 6. Excel 帳票フォーマット要件

- システムのルートディレクトリに template.xlsx を配置すること。
- データシートには、1 日分の入力データを指定の列順で一括挿入すること。
- 列順は、日付、社員番号、氏名、理由、開始時刻、終了時刻、備考とする。
- 印刷シートには、A4 などの印刷前提のレイアウトを保持し、データシートを参照して帳票が自動完成すること。
- 本 PoC では、印刷用の見た目の完全再現を優先し、複雑な制御や高度な書式処理は最小限とする。

---

## 7. 受入条件

- 入力フォームからデータを送信すると、JSON ファイルへ保存されること。
- 画面上に保存成功または失敗のメッセージが表示されること。
- 確定ボタンを押すと、template.xlsx を元に本日の日付の Excel ファイルが生成されること。
- 既存の Excel ファイルがある場合は、backup フォルダへ退避されること。
- 確定後も一時保存ファイルは残り、再出力が可能であること。
- 同じ社員の同一日付データが存在する場合、保存時に最新内容で上書きされること。
- 上書き後は当日分の JSON に同一社員のレコードが 1 件だけ残ること。
- 翌日の最初の入力時に、前日の一時保存データが初期化されること。
- 初心者でも、1 回の試行で入力・保存・確定・印刷まで体験できること。

---

## 8. まとめ

本要求仕様書は、ローカル完結型で簡易に動作する PoC として設計する。教育・演習用途を主目的とし、運用管理の厳密さよりも、入力から保存・確定・印刷までの流れを体験できることを重視する。将来の拡張を見据えた構造を保ちつつ、本フェーズではシンプルな運用とする。
