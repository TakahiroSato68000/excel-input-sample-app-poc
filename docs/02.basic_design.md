# 基本設計書：ローカル完結型データ入力・一括印刷システム (PoC)

## 1. 目的

本設計書は、要件定義書をもとに、Python + FastAPI + HTML + JavaScript を使用したローカル完結型の簡易 PoC を実装するための基本設計を定義する。

本フェーズでは、初心者が入力・保存・確定・印刷までの流れを体験できることを重視し、認証や権限管理などの本格運用機能は除外する。

---

## 2. 設計方針

### 2.1. 基本方針
- ブラウザからアクセス可能な Web アプリとして構成する。
- バックエンドは Python と FastAPI を採用する。
- フロントエンドは HTML と JavaScript を採用する。
- 入力データは JSON で保存し、Excel 出力時に一括変換する。
- 名簿データは roster.json から動的に読み込む。
- 将来 SharePoint などへ差し替え可能になるよう、データアクセス層を分離する。

### 2.2. PoC 前提
- ユーザーごとの認証・権限分離は行わない。
- 画面はシンプルな単一フォームを基本とする。
- 利用者が迷わないように、メッセージと操作手順を簡潔にする。
- 本フェーズでは教育・検証用途を優先し、運用管理機能は最小限とする。

---

## 3. システム構成

### 3.1. 構成概要
本システムは、ブラウザから入力したデータを FastAPI が受け取り、ローカルファイルへ保存し、Excel ファイルへ変換する構成とする。

- フロントエンド: HTML + JavaScript
- バックエンド: Python + FastAPI
- データ保存: JSON ファイル
- Excel 生成: openpyxl などのライブラリ利用を想定
- 名簿データ: roster.json
- バックアップ先: backup/

### 3.2. 実装レイヤー
- UI 層: HTML, JavaScript
- API 層: FastAPI ルーティング
- 業務ロジック層: バリデーション、日付処理、保存処理、確定処理
- I/O 層: JSON 読み書き、Excel 生成、バックアップ処理

### 3.3. 責務分離
- UI は入力と表示に集中する。
- バックエンドは業務ロジックとファイル操作を担当する。
- I/O 層は JSON と Excel の読み書きを独立して扱う。

これにより、将来 SharePoint などの外部保存先へ切り替えた場合でも、UI と業務ルールに影響が出にくくする。

---

## 4. 画面設計

### 4.1. 画面構成
入力画面は以下の要素で構成する。

1. 基本入力欄
   - 日付
   - 氏名
   - 社員番号
   - 開始時刻
   - 終了時刻
  - 理由
   - 備考

2. 操作欄
   - 保存ボタン
   - 確定ボタン
   - 結果表示メッセージ

3. 補助表示欄
   - 名簿候補
   - 入力エラー内容
   - 生成成功/失敗メッセージ

### 4.2. 画面動作
- 画面が読み込まれたとき、当日の日付と現在時刻をデフォルト値として表示する。
- 氏名候補の一覧を先に表示し、選択した氏名を氏名欄へ反映する。
- 入力中に候補を自動表示しない。
- 候補にない氏名でも手入力可能とする。
- 氏名候補から選択した場合は対応する社員番号を自動入力する。
- 保存ボタンを押すと、画面遷移せずに FastAPI へ送信する。
- 保存完了後、メッセージを画面上に表示し、対象日の入力結果一覧を更新する。
- メッセージは入力フォーム、一覧表、Excel 生成ボタンの下に表示する。
- 入力フォームの下に、日付・社員番号・氏名・開始時刻・終了時刻・理由・備考を表示する一覧表を構成する。
- 確定ボタンを押すと、画面で選択中の日付を対象として Excel に出力する。

### 4.3. 利用フロー
1. 入力画面を開く
2. 氏名候補から選択するか、必要に応じて自由入力する
3. 必要データを入力する
4. 保存ボタンを押す
5. 保存結果を確認する
6. 終日分の入力を続ける
7. 確定ボタンを押す
8. 生成された Excel を開いて印刷する

---

## 5. 処理フロー

### 5.1. 保存処理フロー
1. フロントエンドが入力値を収集する
2. FastAPI に POST リクエストを送る
3. サーバー側で必須項目と時刻形式をバリデーションする
4. 保存対象日の JSON ファイルを読み込み、同じ社員番号または氏名が既に存在するか確認する
5. 同一日付で同一社員が既存の場合は、最新入力内容で既存レコードを上書きする
6. 重複がない場合は新規レコードとして追記する
7. 保存結果を JSON 形式で返す
8. フロントエンドが成功/失敗を表示する

### 5.2. 確定処理フロー
1. 当日分の JSON データを取得する
2. 既存の Excel ファイルを確認する
3. 存在する場合は backup フォルダへ退避する
4. template/template.xlsx をコピーして当日用 Excel を作成する
5. データシートに一括書き込みする
6. 生成結果を返す
7. フロントエンドが完了メッセージを表示する

### 5.3. 翌日初回入力時の処理
1. 当日の日付と保存済みデータの日付を比較する
2. 日付が異なる場合、前日分を初期化対象とみなす
3. 新日付の最初の保存時に前日のデータをリセットする

### 5.4. 再出力処理
- 一時保存ファイルは確定後も保持する
- 再出力が必要な場合は一時保存データを再読込し、Excel を再生成する
- 履歴管理や差分管理は本 PoC では対象外とする

---

## 6. データ設計

### 6.1. 入力項目
入力データの基本項目は以下とする
- date: 日付（YYYY-MM-DD）
- employee_number: 社員番号
- employee_name: 氏名
- start_time: 開始時刻（HH:MM）
- end_time: 終了時刻（HH:MM、空欄可）
- reason: 理由
- remarks: 備考

同じ社員の同じ日付データは 1 件だけ残し、最新保存内容で上書きする。判定は employee_number を優先し、未入力時は employee_name を比較対象とする。

### 6.2. JSON 形式
JSON は 1 件ごとにオブジェクトとして保存する。

```json
[
  {
    "date": "2026-09-06",
    "employee_number": "001",
    "employee_name": "山田 太郎",
    "reason": "業務対応",
    "start_time": "09:00",
    "end_time": "17:00",
    "remarks": ""
  }
]
```

### 6.3. 名簿データ
- 名簿は roster.json に記載する
- 形式は社員番号と氏名のペアとする

```json
[
  { "employee_number": "001", "employee_name": "山田 太郎" },
  { "employee_number": "002", "employee_name": "鈴木 花子" }
]
```

### 6.4. 保存ファイル
- 当日データ: data/YYYY-MM-DD.json
- 名簿: roster.json
- バックアップ先: backup/

## 8. Excel 出力設計

### 8.1. テンプレート利用
- template/template.xlsx を元に当日用ファイルを生成する
- 生成ファイル名は YYYY-MM-DD.xlsx とする

### 8.2. データシート
- 現行テンプレートでは `Data` シートをデータシートとして使用する
- 列順は以下とする
  1. 日付
  2. 社員番号
  3. 氏名
  4. 開始時刻
  5. 終了時刻
  6. 理由
  7. 備考

### 8.3. 印刷シート
- 現行テンプレートでは `Print` シートを印刷シートとして使用する
- 印刷用レイアウトを維持する
- データシートから値を参照して帳票が完成する構造とする
- A4 印刷を前提とする

### 8.4. バックアップルール
- 既存ファイルがある場合は backup フォルダへ退避する
- backup は日付付きファイル名で保存する

---

## 9. 例外処理とエラーハンドリング

### 9.1. 入力値エラー
- 日付が空の場合はエラー
- 氏名が空の場合はエラー
- 理由は空欄を許容し、必須ではない
- 時刻形式が不正な場合はエラー
- 社員番号が未入力の場合は警告を返す

### 9.2. ファイル処理エラー
- JSON 保存失敗時は保存失敗メッセージを返す
- Excel 生成失敗時はエラー内容を表示する
- backup 処理失敗時は処理を中断し、ユーザーへ通知する

### 9.3. エラー表示
- 画面上にメッセージ表示領域を用意する
- 成功時と失敗時で区別して表示する

---

## 10. 非機能要件への対応

### 10.1. 研修用途への配慮
- 入力項目を簡潔にし、画面が見やすい構成とする
- メッセージの文言を初心者向けにする

### 10.2. 拡張性への配慮
- I/O 処理を独立させ、将来 SharePoint などへ移行しやすくする
- UI と業務ロジックを切り分ける

### 10.3. 環境要件への対応
- Windows PC 上で動作する構成とする
- 専用 Web サーバーは不要とする
- 同一 LAN 内からのブラウザアクセスを前提とする

---

## 11. 受入条件

- 登録画面から入力したデータが JSON に保存される
- 保存成功または失敗のメッセージが表示される
- 確定ボタンを押すと Excel が生成される
- ファイルが連続して存在する場合、backup へ退避される
- 確定後も一時保存データが残る
- 翌日の最初の入力時に前日のデータが初期化される
- 初心者でも入力から保存・確定・印刷まで体験できる

---

## 12. まとめ

本設計では、FastAPI と JavaScript を使ったローカル環境向けの簡易 PoC を構成する。ユーザー入力を JSON に保存し、確定時に Excel を生成することで、業務の流れを体験できるようにする。

本フェーズでは運用管理を簡略化し、将来拡張可能な構造を保ちながら、教育・検証用途として実装しやすい設計とする。
